# Katton Alpha 0.4.0 — Draft Release Notes

Katton 0.4.0 is a release focused on deterministic script lifecycles, safer
remote synchronization, multi-version distribution, and release reliability.
It supports Minecraft 26.1.2 and 26.2 on Fabric, NeoForge, and Paper with Java
25.

## Highlights

- Added explicit server/client lifecycle phases and typed invocation contexts.
- Made hot reload transactional so preparation failures keep the previous
  active script state.
- Added live Fabric/NeoForge server-pack revisions with staged compilation,
  acknowledgement, timeout handling, and removed-pack deactivation.
- Added external mod/plugin dependency validation and pack dependency ordering.
- Added script-pack `assets/**` and `data/**` mounting.
- Hardened directory, JAR, manifest, packet, hash, and signature input limits.
- Upgraded remote Ed25519 signatures to unambiguous payload format v2.
- Added Minecraft 26.2 alongside 26.1.2 through Stonecutter builds.
- Added structured event and unsafe-injection capability reporting.
- Added startup-agent support for JVMs without dynamic Attach, including an
  FCL-like verification path.
- Added bilingual generated API documentation for common, Fabric, NeoForge,
  and Paper APIs.

## Breaking migration requirements

Before loading a 0.3.x pack:

1. Add `"dependencies": []` (or real declarations) to `manifest.json`.
2. Give world entrypoints an appropriate explicit phase.
3. Re-sign synchronized signed packs so their signature has
   `"payloadVersion": 2`.
4. Update development dependencies to `0.4.0+mc26.1.2` or
   `0.4.0+mc26.2`.

See [Migrating Script Packs from 0.3.x to 0.4.0](migrating-to-0.4.0.md).

## Platform notes

- Fabric and NeoForge provide client execution, registry mutation, networking,
  rendering, and experimental unsafe injection.
- Paper remains server-only and deliberately disables client APIs, registry
  mutation, networking, and unsafe injection.
- Paper supports standard Paper scheduling and the Folia-aware scheduling API.

## Known Alpha limitations

- Paper does not support Ignite-based injection.
- Paper raw loot-table replacement hooks and strongly typed enchanting bridge
  arguments are not complete.
- Entity tick events and NeoForge client block-entity lifecycle callbacks are
  deferred.
- The embedded Kotlin compiler emits a build-classpath warning during Gradle
  configuration; release verification treats it as a known non-fatal warning.

## Release artifacts

The final release must attach six platform/version deployment jars and a
`SHA256SUMS` file generated by:

```text
./gradlew prepareReleaseArtifacts
```
