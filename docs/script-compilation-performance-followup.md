## 本轮结果

| 阶段 | 首次加载 | 同进程修改 manifest 后重载 |
|---|---:|---:|
| 世界包 Kotlin 编译 | 7614 ms | 无编译，内存缓存命中 |
| 服务端准备 | 7696 ms | 8 ms |
| 服务端激活 | 4052 ms | 2331 ms |
| 客户端准备 | 9 ms | 5 ms |
| 客户端 REGISTRY_SETUP 激活 | 4950 ms | 843 ms |
| 客户端 JOINED 激活 | 8556 ms | 228 ms |

世界包首次 Kotlin 编译发生在 `Katton-ServerPreparation`，客户端准备发生在
`Katton-ClientReload`。客户端激活的计时包含等待渲染线程执行；该阶段仍可能让窗口短暂无响应。
测试时临时装入了 `pr_probe` 全局包，它在模组初始化的渲染线程上编译耗时 7714 ms；
正式音游图运行目录已移除该临时包。服务端 READY 至刷怪区准备完成还有约 38 秒日志空白，
不能归因于 Kotlin 编译。线程转储显示启动期间还存在 JAR 解压、类加载和世界资源加载等待。

## 下一步执行顺序与验收

1. 在 `PackRuntime.execute`、`executePackInstance` 和客户端资源重载周围补细粒度计时，
   用 JFR 或线程采样复测正式实例的冷启动，明确 4.95 秒和 8.56 秒分别花在类加载、
   脚本入口、注册表写入还是资源刷新。记录渲染线程实际阻塞时长。
2. 将不依赖 Minecraft 主线程的类加载器构造、入口扫描与解析前移到准备线程；
   将脚本入口和注册表变更保留在平台要求的线程。加入失败回滚和重载期间并发回调的回归验证。
   以正式实例冷启动时客户端激活总时长低于 2 秒为目标；若入口自身超时，单独定位入口。
3. 在不装测试探针的正式实例上做冷启动与重启各一次，确认持久磁盘缓存命中、无渲染线程 Kotlin 编译，
   并记录从启动到可操作的总耗时。并行采样 JAR 类加载与刷怪区准备，处理剩余非编译瓶颈。
4. 复核热重载日志里的 `ManagedCallbackPausedException` 渲染回调告警，避免暂停窗口产生误报，
   同时保留旧脚本世代的隔离与回滚语义。

验收时同时检查脚本能够进入地图、`/katton reload` 成功、客户端无持续未响应、
游戏日志无登录超时或脚本激活失败，并比较每个阶段的耗时。

## 2026-09-27 后续实施与复测

已将宿主 JAR 条目索引前移到准备线程，避免脚本类加载时为每次资源查询重新打开 JAR；
客户端 REGISTRY_SETUP 与 JOINED 在一次渲染线程派发中完成，保留事务上下文；
预期中的 `ManagedCallbackPausedException` 不再作为渲染回调失败告警。
Fabric API 子模块的注册顺序曾在每次启动时变化，导致相同 66 项 classpath 的编译指纹不同。
现在固定外部 classpath 顺序，文件修改时间仍参与失效判定。
